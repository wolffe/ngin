# Three-pass code audit

Date: 2026-09-08. Scope: the source tree, asset-loading paths, runtime ownership, gameplay boundaries, and both website index pages.

This is a source review with focused regression tests, not a claim that every gameplay path is bug-free. All 44 source modules were parsed and their relative imports checked. Input, clock, inventory, and the website were exercised. Vehicle physics, sustained GPU performance, and scene reloads still need dedicated runtime tests.

## Pass 1: Performance and lifecycle

### 1. Texture payload and startup are expensive

At the time of this audit, the sandbox loaded four PBR sets before creating the player and starting the engine. The former PBR loader loaded six 2048 x 2048 PNG maps for each set.

Update 2026-09-09: those sets and the displacement loader have been removed. The sandbox now loads four 1024 x 1024 painterly color textures through [MaterialLibrary.js](../src/graphics/MaterialLibrary.js), with ordinary box geometry. The following measurements describe the old assets, not the current texture load. The website hero now uses a painterly texture derivative as well.

Measured on disk: **24 PNGs, 48,790,715 bytes** (48.8 MB / 46.5 MiB). If uploaded as RGBA8 with a complete mip chain, those textures alone would occupy approximately **512 MiB**. This is an estimate from dimensions and format, not a GPU-memory measurement. It excludes decoded image copies, shadow maps, render targets, geometry, and the environment.

Recommended: retain the source maps, generate smaller runtime variants, and evaluate KTX2/Basis delivery. Load only the sets needed by a game. Start the independent GLB request concurrently with PBR loading. Test cold-cache startup on an integrated GPU and a constrained connection before choosing defaults.

The website now uses a separate **94,528-byte JPEG** derived from an existing texture, instead of downloading the 5,114,382-byte source texture as its hero. The game texture was not modified.

### 2. Simulation time diverges on slow frames

[src/physics/PhysicsWorld.js](../src/physics/PhysicsWorld.js), `step()`, caps rigid-body time at 1/30 second. [src/player/Player.js](../src/player/Player.js) passes the uncapped frame delta to `moveCharacter()`, while the clock allows up to 0.1 second. Particles and weather use a third cap, 0.05 second.

At a steady 20 FPS, rigid bodies receive only about 0.667 simulated seconds per real second, while the character receives one second. This can change riding, carrying, buoyancy, and relative motion. Vehicle cosmetic acceleration also assumes 60 FPS via `(fwdSpeed - prevFwdSpeed) * 60`.

Recommended: one bounded fixed-step accumulator for character movement, force hooks, and Jolt, with an explicit catch-up limit. Validate the same recorded input at 20, 30, 60, and 120 FPS, including carrying on a moving vehicle. Do not change only one local clamp.

### 3. Resource ownership stops at the renderer

[src/engine/Engine.js](../src/engine/Engine.js), `dispose()`, only stops the loop and disposes the renderer. Input, GUI, window listeners, update hooks, the physics world, vehicle constraints/listeners, materials, textures, and the AO pipeline have no coordinated teardown.

[src/player/Occupancy.js](../src/player/Occupancy.js) also keeps the seated occupant in module-global state. A new engine in the same page can inherit an occupied lock. Removing a dynamic body is not a substitute for disposing its vehicle constraints and registered callbacks.

Recommended: establish which module owns each resource; expose idempotent disposers and aggregate them at game teardown. Audit Jolt ownership against the binding API before adding `Jolt.destroy()` calls: borrowed handles and owned allocations must not be treated alike. Test repeated create/dispose cycles and look for growth in hooks, listeners, bodies, constraints, and GPU/native allocations.

### 4. Asset caching does not deduplicate in-flight loads

[src/assets/AssetManager.js](../src/assets/AssetManager.js) caches only successful results. Concurrent requests for the same URL can create duplicate loads, decoded textures, and GLTF parses. Texture and GLTF objects also share one URL-keyed cache, so the two loader APIs can return the wrong resource type if given the same URL. `clear()` only removes references; it is not disposal, and pending loads can populate the cache again afterward.

Recommended: separate typed caches or keys and cache in-flight promises. Evict failures so retries work; define what clearing during an active load means. Keep explicit disposal separate from cache eviction because cloned GLTF instances share resources. Test concurrent calls, failure/retry, and clear-during-load.

### 5. Remaining frame-level waste

- [src/camera/CameraManager.js](../src/camera/CameraManager.js), `setFov()`, rebuilds the projection matrix every frame through the player even when FOV has not changed. Compare the value before updating.
- [src/player/Interaction.js](../src/player/Interaction.js) and [src/player/Use.js](../src/player/Use.js) rebuild prompt HTML every frame. Update the DOM only when the displayed actions or labels change.
- [src/graphics/Particles.js](../src/graphics/Particles.js) marks its instance matrix dirty even when a rate-zero emitter has no live particles. Track live/changed state, hide empty emitters, and stop unnecessary buffer uploads. Keep the existing instancing rather than introducing one mesh per particle.
- [src/assets/placeGltf.js](../src/assets/placeGltf.js), `collectLocalTriangles()`, expands indexed geometry, including attributes the collision collector does not need. Traverse the index and position buffer directly to reduce peak CPU allocation for large assets.
- [src/graphics/AO.js](../src/graphics/AO.js) uses full-resolution, 16-sample GTAO. It is correctly off by default. Profile before increasing the default pixel ratio or enabling AO; offer a lower-resolution tier if needed.

## Pass 2: Gameplay and API edge cases

### 6. Duplicate boat IDs bind the wrong body

[src/vehicle/Boat.js](../src/vehicle/Boat.js) defaults to `boat_${kind}`, adds a body, then looks it up with `getDynamic(id)`. That lookup returns the first matching entry. Creating two fishing boats without explicit IDs therefore assigns the second boat to the first boat's body and replaces its mesh reference; the new body is left without its intended mesh.

Vehicle IDs and some world-object IDs are also fixed defaults. Allocate IDs per instance or reject duplicates in the physics registry. Test two objects of each kind, independent control, and removal of either one. Passing distinct IDs is the current caller-side workaround.

### 7. Vehicle exit ignores terrain height and obstacles

[src/player/Occupancy.js](../src/player/Occupancy.js), `unseatPlayer()`, always uses `halfHeight() + 0.05` for Y. The exit calculation passes only X/Z. Exiting on a raised ramp, hill, elevated platform, or beside a wall can place the player below the surface or inside an obstacle.

Recommended: try exit candidates relative to the vehicle, query ground height, and check capsule clearance. Keep the player seated when there is no valid exit. Test both sides blocked, elevated terrain, water, and overturned vehicles.

### 8. Rejected uncrouching is ignored by visuals and movement

[src/physics/PhysicsWorld.js](../src/physics/PhysicsWorld.js), `setCrouching()`, reports the actual shape state when standing is blocked. [src/player/Player.js](../src/player/Player.js) ignores that return value and chooses visual height, speed, and jump eligibility from the requested key state.

Recommended: derive those states from the accepted crouch state. Test releasing crouch under a low ceiling, then walking out into open space.

### 9. Interaction rays do not account for occluders

[src/player/Interaction.js](../src/player/Interaction.js) intersects only registered targets. A non-interactable wall is not considered, so an otherwise in-range target can be used through it. Descendant visibility is not filtered by application logic either.

Recommended: compare the target hit against a world/physics obstruction hit, with explicit exceptions for the character, carried objects, and invisible interaction proxy meshes. Do not simply discard every invisible proxy: seats intentionally use transparent volumes. Test a crate and seat behind a wall.

### 10. Water displacement is in the wrong local axis

[src/physics/Water.js](../src/physics/Water.js), `createWaterSurface()`, adds the wave to local Y, then rotates the XY plane by -PI/2 around X. Local Y becomes world Z, so this displacement moves vertices along the water plane rather than changing surface height.

Recommended: displace along the plane's local normal or use a consistently oriented geometry. Verify the result at a grazing camera angle and check culling bounds. This is a source-level transform finding; no shader change was made in this pass.

### 11. Some configuration and validation paths are ineffective

[src/engine/Config.js](../src/engine/Config.js) accepts camera FOV/near/far overrides, but [src/engine/SceneGraph.js](../src/engine/SceneGraph.js) hardcodes those values and receives the renderer instead of camera settings. [src/engine/Engine.js](../src/engine/Engine.js), `resize()`, divides the raw width by height even though the renderer clamps zero dimensions. A hidden, zero-height canvas can therefore produce an invalid camera aspect.

Recommended: wire accepted settings into the owning constructor, use the same validated dimensions for renderer and camera, and reject non-finite or negative pixel ratios. Test nondefault near/far values and zero-sized containers.

### 12. Error paths can leave a blank sandbox

At the audit date, the demo startup did not catch asynchronous game creation failures. Model, texture, renderer, or WASM failures could abort initialization without an in-page recovery state. The current [sandbox startup](../games/sandbox/scripts/main.js) now reports boot failures; the demo was subsequently relocated into its own game folder. The [sandbox implementation](../games/sandbox/scripts/sandbox.js) still reads/writes localStorage without handling storage-policy errors.

Recommended: one startup error boundary with a useful failure message and retry path, plus guarded preference persistence. Test an unavailable CDN, failed model request, and denied storage. Do not silently substitute broken physics or hide required asset failures.

### 13. Dynamic prompt labels are still interpreted as HTML

Inventory names are now rendered as text. However, [src/player/Interaction.js](../src/player/Interaction.js) still interpolates `getText()` / `getAltText()` and action labels into `innerHTML`. GLTF display names reach those callbacks. Existing callers use trusted data, but this is unsafe if names later come from user-authored levels or remote content.

Recommended: render text nodes and separately created key-label elements, sharing that renderer with the held-item prompt. Test labels containing `<`, `&`, and HTML-like strings. This is not a claim of a currently exposed remote exploit.

## Pass 3: Simplification, dead code, and DRY

- **No orphan source modules found at audit time.** The demo entry and intended starter were the exceptions to source-module inbound imports. They have since moved to the [sandbox bootstrap](../games/sandbox/scripts/main.js) and [starter game](../games/template/scripts/game.js), each launched by its own game page.
- **Removed verified unused locals:** the two unused Three.js wheel vectors in [src/vehicle/Vehicle.js](../src/vehicle/Vehicle.js).
- **Removed a forwarding-only wrapper:** voxel materials now call `createMappedMaterial()` directly in [src/world/VoxelHill.js](../src/world/VoxelHill.js).
- **Preserved public helpers:** `createFlyCamera`, `syncFromCamera`, `createLighting`, and `codeToActions` have no current source callers. `createLighting` is documented; unused exports are not automatically dead APIs. The reverse action map now has no runtime consumer after the input simplification. Decide whether external consumers need it before deprecating it.
- **Existing sharing worth keeping:** `bindSeat()` already centralizes car/boat occupancy, `attachLamps()` handles shared light behavior, and `createParticleEmitter()` centralizes effects. Keep tuning differences in profiles; avoid merging all world factories into a generic configuration framework.
- **Duplicate key handling:** sandbox and template both attach a raw V-key listener outside the action map. Those listeners accept key repeat and editable-field events. Move view switching into the mapped, edge-triggered input path with tests; the input-manager fix alone does not govern these separate listeners.
- **Website styles now share tokens and primitives:** [public/styles/site.css](../public/styles/site.css) owns typography, theme colors, focus treatment, prompts, and common controls. Old decorative landing-page CSS was removed.
- **Documentation cleanup:** removed the repeated checklist heading in [docs/new-game.md](new-game.md). Existing homepage messaging and handbook paragraphs/prompts were retained.

## Reproduce verification

The runtime still requires no Node installation or build step. These checks are optional development tools, tested with Node 24 and installed Chrome on Windows.

```powershell
C:\php\php.exe -S localhost:8080
node --test tests/*.test.mjs
node tests/browser-check.mjs
```

The browser check supports `CHROME_PATH` and `NGIN_URL` environment overrides. It writes website-only captures to a temporary folder, not to the game's assets.

Results: **7 regression tests passed**; both pages passed at 1440 x 900, 390 x 844, and 320 x 740, plus desktop dark mode. Reduced-motion mode was enabled during layout checks. Local links/fragments, image decoding, native disclosures, active handbook navigation, and inventory text safety passed. Source syntax and relative imports passed for all 44 modules.

Not performed: Lighthouse, Playwright (optional installation was skipped), cross-browser/device testing, a full accessibility audit, gameplay scenario playtests, sustained FPS profiling, or native-memory leak measurement. The browser checks use Chrome's native DevTools protocol without extra dependencies. No in-game screenshots were captured or added. This folder has no Git metadata, so a baseline diff was unavailable.
